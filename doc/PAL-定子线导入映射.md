# PAL 定子线导入映射

内部标识为 `pal_stator`。客户表以项目栏 `PA stator housing` 和工作表 `Open points list` 识别，豪森补充版用 `Stator housing`。读取字段表头，忽略其他报告页和表尾图例。首次扫描可识别旧 EOL 资料夹内的独立定子工作簿，以及 `PAL_Stator` 根目录中的豪森副本。后续版本建议分别放在 `PAL_Stator/List/ZF/` 和 `PAL_Stator/List/Haosen/`。

| 源列 | 数据与使用规则 |
|---|---|
| No.、Problem | 客户编号为主。同号问题用稳定后缀区分；空号带描述的行保留在核对队列。人工确认客户已分配编号后可补号建账。 |
| Author、Status changed by | 提出者与客户状态变更人各自保留。提出者筛选支持五个人名的姓氏与全名，原始拼写可在版本中查看。豪森负责人列出现客户姓名时生成核对提示。 |
| Station number、Variant | 解析单工位及多工位缩写，例如 `201-050/051`。工位为空时从 Variant 识别工位或设备名。Elevator 和 Lift 归入升降机；包含明确工位号的 Lift 也可按该工位查找。All / Allgemein 显示为全线。Binar 等限定词在客户原文中保留。 |
| 三个 Date | 第一处为提出日，紧随 Responsible 的为客户期限，紧随 Status changed by 的为客户状态变更日。豪森补充版期限不同且可解析时存为建议日期，可在详情确认实施计划。 |
| Action | 客户原文按日期分段。豪森补充逐段与已归档的客户原文比对，有明确独立日期的中文新增反馈按业务日入库；仅凭相同日期无法判断归属时由现场选择反馈、译文或保留原值。反馈保留来源行，跨版本按问题、日期与正文去重。 |
| Priority、Responsible、Status | 共用优先级、ZF 责任及客户状态规则。我方状态机采用会议决定和有效的客户版本变更。 |
| 整改人数、负责人、整改时间、投产单号 | 补充我方资料。已有现场值冲突时提交核对；仅在确认后覆盖。 |

## 现场核对

自动返工沿用[测试线开发设计](EOL-问题管理开发设计.md)第 2.3 节的客户版本流转规则。仅比对两次客户导入的 Action。豪森版在同一列录入的现场反馈保留在现场时间线上。

豪森部分行在编号和工位不变的情况下，描述来自相邻问题。自动关联要求编号与内容相互印证。如果只有客户行动、编号、工位、日期和提出者相符，可单独提取有依据的反馈，同时把其余字段列入待核。核对时对照来源行、候选客户原文和 Action，再决定是否绑定。未带客户编号的豪森描述可绑定已有问题。

周报覆盖定子线所有客户编号。跨工位问题在各相关工位分别计数，全线总数只计一次，工位小计不可直接相加。现场反馈、客户行动和建议日期各自保留业务含义。
