# 多线体现场问题工作台

一个本地服务提供项目概览、问题清单、专项任务、项目周报和导入核对。页顶线体选择器显示当前工作区。切换时打开目标线体的同一模块，清除本页的问题弹窗；返回某条线的问题清单时可找回该线最近的筛选。

| 线体 | 页面和 API | SQLite 数据文件 | 生产资料 |
|---|---|---|---|
| EOL 测试线 | `/`、`/api/` | `data/opl.sqlite3` | `EOL/` |
| PAL 定子线 | `/lines/pal_stator/`、`/lines/pal_stator/api/` | `data/lines/pal_stator/opl.sqlite3` | `PAL_Stator/` |

## 模块接口

- `opl/lines.py` 定义固定线体标识、显示名、URL、数据库目录和分期能力。Flask 为每条线挂载同一组路由。浏览器按页面所属的线体发送请求，操作人可在同一浏览器共用。
- `source_paths(root, line)` 发现客户和豪森文件。首次启动及目录同步优先导入客户版本。工作簿按内容指纹去重；手工预览和命令行使用同一个 `read_book(path, line)`，得到来源角色、工作表名称及标准字段行。原始行快照随导入批次归档。
- `station_fields` 调用线体对应的工位解析器。每个问题有独立内部 ID。多工位保存成员列表，筛选与工位统计使用同一份成员。整线数量按内部 ID 计算。
- `import_book` 在当前库的一个事务内写入版本、问题、行动、反馈和待核项。共用状态机、行版本检查、问题关系和任务逻辑。任务里的问题 ID、附件和客户号都在当前线体内解释。
- 清单导出沿用屏幕筛选，下载文件、派工单标题、详情链接和周报归属当前线体。EOL 沿用分期规则和旧书签。定子线使用全线与工位汇总。

## 本地部署与交接

一键启动和依赖版本沿用现有配置。同步单条线可运行 `python -m opl sync --line pal_stator`；不带参数的同步命令扫描两条线。指定文件时同时指定所属线体，EOL 仍是显式文件的默认目标。

使用 `python -m opl backup --line pal_stator` 和 `python -m opl backup --line eol` 分别保存数据库、已索引证据和已导入原件。恢复命令将文件解包到新目录并校验哈希及 SQLite 完整性。定子线恢复后位于原相对路径，旧版 EOL 备份沿用原恢复方式。

## 回归验收

自动化覆盖两线内部 ID 与客户号重复、专项任务隔离、错误线体上传、来源下载路径、定子线单独备份恢复、多工位筛选与周报。浏览器场景从带筛选的测试线切到定子线，打开同号问题、查看定子周报，再返回原线的清单。业务字段的对应关系见 [定子线导入映射](PAL-定子线导入映射.md)。
